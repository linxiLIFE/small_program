# CloudBase MySQL 初始化与权限

业务数据已切换到 CloudBase 原生 MySQL。小程序客户端不直连数据库，只调用 `api` 云函数；后台、任务和种子函数使用服务端 `mysql2` 连接池。这样可以避免客户端伪造价格、OpenID、角色、积分余额和订单状态。

## SQL 表

在 MySQL 数据库执行 [`mysql-schema.sql`](mysql-schema.sql)，创建以下 19 张 InnoDB 表：

```text
users staff_accounts categories services works technicians
schedule_templates technician_days orders payments refunds
points_accounts points_ledger jobs notification_records audit_logs
daily_metrics settings_versions idempotency_keys
```

每张表包含 `id` 主键、`data` JSON 业务载荷、`created_at` 和 `updated_at`。资金与任务表另有从 JSON 派生的生成列、查询索引和资金编号唯一约束。嵌套快照和排班数组保存在 `data`，订单、积分和任务的写入由 MySQL 事务完成。SQL 适配层只允许白名单表名，值全部使用参数化查询。

`seed` 函数只负责非生产演示目录，不在生产部署清单内。即使临时部署，也必须同时设置 `SEED_ENABLED=true`、至少 32 字节的 `SEED_ADMIN_SECRET`，并提交 `confirm=SEED_DEMO_DATA` 与对应 secret；不要把它当作正式业务数据导入工具。

## 连接与权限

在每个需要访问数据库的云函数配置以下服务端环境变量：

```text
DB_HOST       MySQL 内网连接地址
DB_PORT       3306
DB_USER       必填，使用专用业务账号，禁止依赖 root 默认值
DB_PASSWORD   数据库密码
DB_NAME       数据库名，默认 tcb
```

云函数必须绑定 MySQL 所在 VPC/子网，优先使用内网连接；`DB_PASSWORD` 只在 CloudBase 服务端受控配置中保存，不写入仓库、前端或日志。不要为了让页面显示数据而打开客户端直连。

业务函数每次执行身份、角色、对象归属、状态和金额校验；MySQL 账号遵循最小权限原则。数据库管理账号仅用于初始化表结构，业务函数账号至少需要业务表的读写权限。本次线上业务账号为 `shiguang_app`，密码不记录在文档中。

## 主键与查找键

当前 schema 为每张表创建 `id` 主键和时间基础索引。资金与任务表还包含：

- `technician_days` 使用 `技师ID_日期` 作为 `id`；
- `payments` 使用 `pay_订单ID`，`merchant_order_no` / `transaction_id` 唯一；退款失败后可使用 `rf_订单ID_尝试次数` 新退款单号，`refund_no` 唯一；
- `orders` 的用户、状态、技师与开始时间，`jobs` 的状态与执行时间均有生成列索引；适配层优先使用这些列，旧库未迁移时只做兼容回退；
- `points_accounts` 使用 `openid` 作为 `id`，`idempotency_keys` 使用哈希后的幂等键作为 `id`。

## 初始化顺序

1. 在 CloudBase 开通 MySQL，确认实例进入可用状态。
2. 新库运行 `npm run db:schema` 执行 `docs/mysql-schema.sql`；已有库先备份并逐项确认无重复资金编号，再依次执行 `docs/mysql-finance-index-migration.sql` 和 `docs/mysql-analytics-index-migration.sql`，最后从 `information_schema` 核对生成列、索引与唯一约束。
3. 为云函数配置 MySQL 内网连接环境变量和 VPC/子网。
4. 仅在隔离的非生产环境临时部署并执行 `seed`；生产环境不部署。
5. 在 CloudBase 身份认证用户管理中创建首位用户名密码用户，取得预先指定的 UID 后，通过下方受控脚本创建唯一首个 `OWNER`；不开放公众注册，也不通过网页初始化权限。
6. 用顾客账号测试目录、报价、订单归属和积分；用店员/技师账号测试最小权限。

当前环境的函数和静态入口已经通过 CLI 配置；后台地址和首个账号初始化见 [`README.md`](../README.md)。重新部署函数前先运行 `npm run prepare:functions`，不要把数据库密码补回 `cloudbaserc.json` 或提交到仓库。

## 首个店主初始化

线上 API 不提供“当前登录者成为 OWNER”的入口。先在 CloudBase 创建内部登录账号并取得其 UID，再由受控运维终端执行一次：

```bash
BOOTSTRAP_OWNER_UID='<预先指定的 CloudBase UID>' npm run admin:bootstrap-owner
```

脚本仅在不存在任何 active staff 时写入 `staff_owner`；已有管理员时不会覆盖或追加 OWNER。不要把 UID 以外的登录凭据写入仓库。
