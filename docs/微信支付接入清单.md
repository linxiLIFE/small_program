# 微信支付接入清单

当前代码已经预留支付能力，但尚未验证个体工商户资质，也没有把任何支付密钥写入仓库。拿到资质后按下面顺序补填。

## 需要在服务端填写的变量

| 变量 | 作用 | 是否允许进小程序/浏览器 |
| --- | --- | --- |
| `WX_APPID` | 小程序 AppID | 否，支付服务端使用 |
| `WX_MCH_ID` | 微信支付商户号 | 否 |
| `WX_MCH_SERIAL_NO` | 商户证书序列号 | 否 |
| `WX_API_V3_KEY` | API v3 对称密钥 | 否 |
| `WX_PRIVATE_KEY` | 商户 API 证书私钥，可用 `\\n` 表示换行 | 否 |
| `WX_NOTIFY_URL` | `payment-callback` 的公网 HTTPS 地址 | 否，服务端配置 |
| `WX_PLATFORM_CERT_PEM` | 微信支付平台证书，用于通知验签 | 否 |
| `CONTACT_ENCRYPTION_KEY` | 32 字节联系方式 AES-256-GCM 密钥，支持 64 位 hex 或 base64 | 否 |
| `QUOTE_SIGNING_SECRET` | 后续可用于报价令牌签名的服务端密钥 | 否 |

新环境当前的 `payment-callback` 已部署为事件型云函数，尚未创建公网 HTTPS 访问路径，因此暂时没有可填写的 `WX_NOTIFY_URL`。完成支付资质后，先为该函数配置公网 HTTPS 访问，再把实际地址写入 CloudBase 服务端变量。

```text
（待配置 payment-callback 公网 HTTPS 地址）
```

当前只验证了函数部署，尚未用微信真实通知完成验签解密。

代码只会在配置完整时调用 JSAPI 下单。配置不完整时订单仍可保留，页面显示“支付待配置”，不会伪造成功。

## 资质和配置步骤

1. 完成小程序主体认证，确认个体工商户主体可以申请小程序支付权限。
2. 申请普通商户号，确认商户号与当前 AppID 绑定。
3. 创建 API 证书，记录商户证书序列号和私钥；私钥只进入 CloudBase 服务端受控配置。
4. 设置 API v3 密钥并保存到密码管理器，再写入云函数环境变量。
5. 部署 `payment-callback`，配置公网 HTTPS，确认微信侧回调地址可访问且不会改写原始请求体。
6. 配置平台证书，先验签和解密测试通知，再打开真实交易。
7. 用真机完成支付、服务端查单、支付取消、5 分钟关单、迟到支付自动退款、用户取消退款和退款成功通知。

## 不能用来判断成功的信号

- 小程序前端 `wx.requestPayment` 的 `success` 只说明调起流程返回，不等于服务端已确认到账。
- 微信退款接口受理成功只代表申请已受理，不等于用户已经到账。
- 只能依据支付回调或服务端主动查单更新支付终态，并根据退款回调或退款查单更新退款终态。
