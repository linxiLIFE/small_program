## 上线顺序

1. 在目标 MySQL 实例中执行一次 `docs/mysql-product-features-migration.sql`。
2. 为业务云函数配置独立的 `CHECKIN_SIGNING_SECRET`（至少 32 字节）；未配置时会兼容使用已有 `QUOTE_SIGNING_SECRET`，但生产环境建议分离密钥。
3. 依次部署 `api`、`admin-api`、`jobs`、`payment-callback`。本功能不需要部署 `seed`。
4. 发布管理后台，在“门店与预约设置”中确认取消时限、未到店宽限、违约金、邀请积分和订阅消息模板。
5. 上传小程序体验版，分别用顾客、对应技师、其他技师和店主账号验证二维码权限。

## 微信订阅消息配置

需要在微信公众平台“订阅消息 / 我的模板”准备四类模板：预约成功、提醒到店、核销成功、未到店退款。将模板 ID 与实际关键词字段名填入管理后台。默认字段示例为：

- 项目：`thing1`
- 时间：`time2`
- 技师或地址：`thing3`
- 退款金额：`amount2`
- 退款状态：`phrase3`

关键词必须以公众平台中实际模板为准。顾客授权是一次性订阅：预约提交时申请预约成功、到店与未到店提醒；订单详情页可单独申请核销成功提醒。

## 验收清单

- 顾客付款成功后能在订单详情打开二维码；二维码被修改、过期或属于其他订单时拒绝核销。
- 对应技师可以核销，其他技师得到无权操作提示；店主或员工可以核销全店订单。
- 距预约开始小于后台设定的取消时限时，顾客端取消入口消失，服务端直接调用也会拒绝。
- 开始后超过宽限仍未核销的订单进入未到店结算：积分抵扣部分先承担违约金，剩余违约金扣现金，余额退款；订单总额低于违约金时不退款。
- 邀请码不能自绑、不能重复绑定；双方积分与积分流水只增加一次。
- 预约成功、提醒到店、核销成功、未到店退款四类消息分别用真机完成授权与送达验证。
- 管理后台组合筛选、分页、自定义统计周期、状态分布和预约时段热力图与数据库抽样一致。
